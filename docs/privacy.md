# Shoggoth 产品统计隐私说明

更新于 2026-11-26，适用于产品统计格式 v3。

在启用产品统计的官方正式桌面版本中，**设置 → 隐私与统计 → 分享使用数据** 默认开启。关闭后会停止产品统计并清除未发送的数据。升级会保留以前的选择，包括仅统计基础活跃。桌面 App 启动环境中的 `DO_NOT_TRACK=1` 或 `SHOGGOTH_TELEMETRY_DISABLED=1` 也可关闭统计。

维护者用统计数据了解活跃安装、版本分布、功能采用和操作质量。每份应用数据目录使用一个随机安装 ID。打开主窗口或把它唤回前台，当天即记一次活跃，打开后直接退出也算。窗口隔夜打开时，次日的首次前台操作也能计入。每个 UTC 日最多一次。后台服务单独运行不会增加日活。v2 及更早版本需要一次前台操作才计活跃。

## 采集内容

| 范围 | 数据 |
| --- | --- |
| 基础活跃 | 随机安装 ID、随机事件 ID、UTC 时间与日期、应用版本、系统类别、CPU 架构、数据格式和策略版本。 |
| 详细功能 | 主动使用的页面类别，单聊、群聊、灵感、任务、定时任务、模型、技能、助理和连接器操作的每日尝试、成功、失败和取消次数。群聊成功指用户消息已提交，任务和定时任务以操作请求可确认的结果为准。 |
| 操作质量 | 固定错误类别（网络、超时、需要认证、权限、不支持、验证失败、未知）及耗时区间（小于 1 秒、1–5 秒、5–30 秒、30–120 秒、120 秒及以上）。 |
| 单聊、连接器和后台任务 | 单聊发送与连接器授权按上述七类错误分别汇总次数。当天手动打开过已完成的后台任务卡片时，日报会记录这一项。 |
| 配置与采用 | 已配置的后端、助理运行时、供应商和模型，以及聊天执行结果可确认的运行时、供应商和模型。记录已启用的公开连接器及类别、技能数量与来源类别、助理和配置数量。配置来自 App 成功读取的当前视图。没有读到的类别标记为缺失，未确认的执行结果归为未知。 |
| 配置转化 | 用户开始配置、明确触发的连接验证成功和首次聊天成功。每份应用数据目录每个步骤最多记一次。 |

详细功能在本地按 UTC 日汇总。公开供应商、模型和连接器名称只从随 App 发布的白名单取值，自定义条目只使用固定类别。每份汇总会带公开目录版本，以及适用的覆盖范围、截断或计数上限标记。

**模拟示例**　同一天打开 App 三次、成功单聊两次、打开已完成任务的详情一次，基础活跃计一次，功能日报会包含 `chat_send_success_count: 2` 和 `opened_completed_background_task: true`。[事件字段定义](../app/core/product-telemetry-schema.js) · [公开功能与模型目录](../app/core/data/product-telemetry-catalog.json)

统计字段排除消息、提示词、回复、工具内容、聊天和任务正文、灵感便签、助理设定、搜索或输入内容、文件名和路径、URL、凭据、用户名、邮箱、账号及业务会话标识、精确 Token 用量、费用、日志、截图、录屏和硬件指纹。这些值的哈希也在排除范围内。

## 发送与保留

基础活跃和配置步骤会在记录后尝试发送。详细汇总在 UTC 跨天后封存，可能在下次启动时才发送。离线事件的补发期限为 7 天，完全退出期间的过期缓存会在下次运行时清理。关闭会取消在途请求并清除待发送数据，重新开启只记录后续打开和操作。普通关闭会保留本地随机安装 ID 和用于防止重复计数的有限标记。

官方正式版本通过 HTTPS 向 PostHog Cloud 美国区（`us.i.posthog.com`）发送统计。项目丢弃客户端 IP，应用禁用 GeoIP 补充和用户档案。接收方网络层可以看到连接的源 IP，随机安装 ID 可以关联同一安装多天的活动。项目的事件保留设置为一年。PostHog 按月分批清理，到期事件可能额外保留约两个月，已删除数据在备份中通常再保留约两周。[PostHog 数据存储说明](https://posthog.com/docs/privacy/data-storage)

关闭统计无法撤回已经收到的数据。如有隐私问题或删除请求，请通过项目的 [GitHub Issues](https://github.com/ArronKong/Shoggoth/issues) 请求维护者提供后续联系渠道，公开帖子中请勿提交身份、密钥或安装标识。

上述开关控制 Shoggoth 产品统计。你主动使用的模型供应商、外部连接器和运行时按各自的设置与服务条款处理业务请求。

## 手动创建诊断文件

在「应用诊断」点击「创建诊断文件」，选择保存位置，就能在本机查看应用版本、系统类别和错误摘要。取消保存即结束。每种错误列出固定错误码、最近一次出现的时间（UTC）、发生次数和出错环节。同一码出现在多个环节时，每个环节也有自己的次数和最近时间。

次数来自本机最近保留的启动故障和后台服务运行故障，每类最多 8 条。同一条故障中重复出现的错误码只计一次。旧记录会显示当时能确认的进程和阶段，例如 MCP 辅助进程启动。关闭使用统计也能生成文件，是否向支持团队分享由你决定。
